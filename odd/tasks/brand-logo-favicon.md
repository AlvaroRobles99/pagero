# Brand Logo + Favicon

## Objective

Use the user-provided `public/images/logo.png` as the site's visible logo (Hero) and as the
browser favicon + iOS home-screen icon, replacing the lotus `public/favicon.svg`.

## Problem

The page has no logo — the brand identity in the Hero is text-only. The favicon is still the
old lotus SVG. Rocío produced a brand logo file and wants it used both on the page and in the
tab/iOS icon.

## Why

User request: "usa esta imagen para logo de la pagina y favicon", providing
`public/images/logo.png`.

## Scope

### In scope
1. **Hero logo** — logo image above the `h1` in the Hero.
2. **Favicon pipeline** — script deriving favicon PNGs + `apple-touch-icon` from `logo.png`.
3. **`index.html` rewiring** — icon links point at the new PNG set; JSON-LD `logo` points at
   `/images/logo.png`; `public/favicon.svg` is removed.
4. **Tests** — update the favicon contract, assert the Hero logo and the on-disk icon assets.
5. **Docs** — `AGENTS.md` + `docs/project.md` reflect the new files.

### Out of scope (do NOT invent)
- **`og:image`** — stays as-is (`og-image.png` is a separate designed asset).
- **PWA manifest / service worker** — not requested.
- **Absolute URLs** — deploy-time step unchanged (domain still undecided).
- **Design of the logo itself** — asset is fixed, user-provided; we only place and derive from it.

## Constraints

- **Artifact language:** English for code, comments, identifiers, and test descriptions;
  `docs/project.md` edits in **Spanish** (the file is Spanish); `AGENTS.md` edits in **English**.
  UI copy unchanged.
- **Zero new dependencies.** Reuse the existing `@resvg/resvg-js` devDependency for raster
  generation, exactly like `scripts/generate-og.mjs`. If resvg cannot embed the PNG, STOP and
  report — do not add `sharp` or any other package.
- Repo is under git on branch `feat/home-content-rewrite`. The delegated writer does NOT
  commit; the orchestrator verifies first and closes with the work-unit commit.
- `public/images/logo.png` is currently untracked — it must end up committed with the feature.

## Logo asset analysis — VERIFIED programmatically (this model has no image input)

| Fact | Evidence |
|---|---|
| 1254×1254, `Format32bppArgb` | System.Drawing metadata |
| Transparent background: only **35.8%** opaque pixels | sampled every 8th pixel |
| Shape: opaque bbox 1192×1160, **aspect 1.03 → square symbol, NOT a wordmark** | bbox scan every 4th pixel |
| Color: **light** warm-white mark (avg luminance 220, avg RGB 233/216/212), lum range 25–255 | opaque-pixel stats |
| Margins inside canvas: ~3% each side | bbox offsets (32/30/40/54) |

**Design implications (decided, do not relitigate):**
- Light mark on transparent bg → renders well over the dark Hero banner; sits above the `h1`
  without duplicating it (it is a symbol, the `h1` carries the name).
- The SAME light mark is **invisible on a light browser tab** → every favicon/apple-touch-icon
  output must be composited onto an opaque `#1f0f14` backing with ~12–14% padding.
  `apple-touch-icon` must be fully opaque (iOS renders transparency badly).
